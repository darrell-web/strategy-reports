PILLAR 02

2The 5-Minute Visit Diagnostic

Same diagnostic framework as Charlotte's review-velocity work — different question. East Lansing customers complete their visit in half the chain-standard time. Why?

HypothesisTest
H1: Heavy app / online pre-order — customers walk in to pick up, not browsePOS data — what % of East Lansing transactions originate via online order vs in-store-walk-in?
H2: Different menu architecture — perhaps East Lansing has cleaner Dutchie/Sweed integration that supports faster decision-makingAudit menu rendering at East Lansing vs Big Rapids. Is the in-store digital menu / kiosk different?
H3: MSU student demographic moving between classes — fast-cycle, decisive shoppersPOS data — repeat-customer rate + visit-frequency distribution. If it skews more frequent / shorter, demographic is the driver.
H4: High-velocity POS — checkout itself is faster (more registers, better-trained staff, different flow)Observe checkout at East Lansing vs other store. Time the average transaction.
H5: Different store layout — products laid out for fast browsingPhoto audit + GM interview.

If H1 is the driver: chain-replicable via online-pre-order push in AIQ + UX optimization. If H2: replicable via menu integration audit. If H4: replicable via staff training + register count. If H3 alone: structural; not replicable but reframes chain expectations.

Implication for AIQ campaign timing

Standard chain default: post-visit AIQ campaign fires ~10 minutes after visit complete. At East Lansing's 5-minute visit profile, the customer is already gone before the SMS / push arrives. Test 3-5 minute fire times for East Lansing specifically — this is the single most-impactful AIQ adjustment for this store.
